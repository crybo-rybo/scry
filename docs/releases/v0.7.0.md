# Scry v0.7.0

Scry v0.7.0 replaces the scripted transport of `scry::testing` with a scripted
HTTP server on loopback. A scripted test now runs all of the shipping code,
libcurl and HTTP included. This release also fixes Anthropic-compatible servers
that stream thinking blocks, and it fixes the result of `Turn::cancel()` after
its `Harness` is gone.

This is a minor release because it removes the `ScriptedTransport` API from the
`testing` package component. The public headers of `scry::scry` change only in
their documentation comments.

## Breaking changes

### `ScriptedServer` replaces `ScriptedTransport`

`<scry/testing/scripted_transport.hpp>` is removed. Use
`<scry/testing/scripted_server.hpp>`.

`scry::testing::ScriptedServer` is an HTTP/1.1 server on 127.0.0.1 with an
ephemeral port. A test sets `Config::base_url` to `server.url()` and calls the
ordinary `Harness::create`. The server sends each body chunk as one HTTP chunk.
Thus, a scripted turn runs libcurl, the HTTP response policy, SSE framing, the
provider encoder and decoder, retries, tool dispatch, and the pump.
([#134](https://github.com/crybo-rybo/scry/pull/134))

| Removed or changed | Use instead |
|---|---|
| `ScriptedTransport transport;` | `auto server = ScriptedServer::create();` It returns a `Result`. |
| `create_harness(config, transport, tools, seed)` | Set `config.base_url = server->url()`, then call `Harness::create(config, tools)`. |
| The `retry_jitter_seed` argument | Set `config.retry.jitter_ratio = 0` for reproducible retries. |
| `ScriptedResponse::request_id` | `.headers = {{.name = "request-id", .value = "..."}}` |
| `ScriptedResponse::failure` | A status, for example `429` for `rate_limit`, or `close_after_chunks = 0` for a retryable `network` failure. |
| `CapturedRequest::url` | `CapturedRequest::target`, for example `/v1/messages`. `method` is new. |
| `calls()` | `requests().size()` |
| `wait_for_call(count)` | `wait_for_request(count, timeout)`. It returns false after the timeout. The default timeout is 10 s. |
| `release()` releases all holds, now and later | `release()` lets one hold or pause continue. |

New in `ScriptedResponse`:

- `pause_after_chunks` stops after a number of chunks until `release()`. The
  host can observe the delivered output, or cancel the turn.
- `close_after_chunks` closes the connection before the chunked body ends.
  libcurl reports a retryable `network` failure. With 0, no body byte arrives,
  so Scry retries the request.
- A request that arrives when the script is empty gets status 404 with an
  `unscripted_request` error body. Scry reports a `protocol` failure, and its
  `provider_detail` ends in `:unscripted_request`.

When a host cancels during a hold or a pause, the server stops that response and
serves the next connection. libcurl can take up to `Config::timeouts.shutdown`
to see a cancelled turn, so set that bound low in tests that cancel. When you
destroy the server, it closes open connections. This is also true when a client
does not read.

`examples/testing_scripted.cpp` shows the new form.

## Fixes

- **Anthropic thinking blocks.** Some Anthropic-compatible servers, for example
  Ollama, stream `thinking` blocks when the request does not ask for them.
  Before, the stream decoder rejected the turn. Now it reads `thinking` and
  `redacted_thinking` blocks and their `thinking_delta` and `signature_delta`
  events, and it drops them. A dropped block makes no event, and it does not
  go into committed history. Thus, Scry does not send it back. Other unknown
  blocks and misdirected deltas still fail with `protocol`.
  ([#135](https://github.com/crybo-rybo/scry/pull/135))
- **`Turn::cancel()` after its `Harness` is gone.** Before, it returned true,
  but it did nothing. The turn had already ended, and `finished()` returned
  true. Now it returns false.
  ([#128](https://github.com/crybo-rybo/scry/pull/128))

## Documentation

- The README, `docs/architecture.md`, `docs/contributing.md`, and the release
  notes now use ASD-STE100 Simplified Technical English.
  ([#125](https://github.com/crybo-rybo/scry/pull/125))
- API comments are correct now:
  - `Conversation`: `update()` commits history when it processes the terminal
    event. This occurs before `on_finished` runs, and also when there is no
    `on_finished`.
  - `UniqueFunction`: an empty `UniqueFunction` throws
    `std::bad_function_call` when you call it.
  - `Harness::tools()`: the `Harness` must not be moved-from.
  ([#129](https://github.com/crybo-rybo/scry/pull/129))

## Build and contributor tooling

- **Scripts.** CI calls four scripts directly: `scripts/test.sh` for each
  preset, `scripts/format.sh`, `scripts/lint.sh`, and `scripts/test-e2e.sh`.
  `test.sh` runs `ctest` in parallel. CI runs on Ubuntu 24.04 with GCC 16. It
  runs the `dev`, `asan`, and `tsan` presets, a clang-format 22 check, and
  clang-tidy 22 on the kernel.
  ([#126](https://github.com/crybo-rybo/scry/pull/126),
  [#129](https://github.com/crybo-rybo/scry/pull/129))
- **Removed.** The `ci` and `fuzz` presets, the `SCRY_CLANG_TOOLING`,
  `SCRY_BUILD_FUZZERS`, and `SCRY_ENABLE_CLANG_TIDY` options, most `cmake/`
  helper modules, the Doxygen site, the package-consumer project, lizard, the
  release workflow, and `.editorconfig`. clang-tidy reads the kernel with plain
  flags, so it needs no CMake mode. Each fuzz corpus replays as an ordinary
  test in each preset. ([#126](https://github.com/crybo-rybo/scry/pull/126))
- **Releases.** No workflow publishes a release now. Push the tag and run
  `gh release create` by hand, as `docs/contributing.md` tells.
- **Live smoke test.** `scripts/test-e2e.sh` runs on each dialect. Set
  `SCRY_E2E_BASE_URL` and `SCRY_E2E_MODEL`. `SCRY_E2E_DIALECT` is `openai`
  (the default) or `anthropic`. `SCRY_E2E_API_KEY` is necessary only for
  `anthropic`. The test runs a typed `ask<T>()`, a
  streamed turn with one reflected tool round, and a follow-up turn on a
  conversation that it saved and restored.
  ([#133](https://github.com/crybo-rybo/scry/pull/133))
- **Tests.** The integration and transport suites now use only the public API
  and `ScriptedServer`. They need `SCRY_BUILD_TESTING_SUPPORT`, which is on by
  default. New tests cover adjacent assistant messages after a rejected typed
  answer, for both dialects.
  ([#132](https://github.com/crybo-rybo/scry/pull/132),
  [#136](https://github.com/crybo-rybo/scry/pull/136))
- **Internal refactors** with no change in behavior: one tool encoder for both
  dialects, one JSON root-object check, and one completion record from the turn
  machine to the pump.
  ([#130](https://github.com/crybo-rybo/scry/pull/130),
  [#131](https://github.com/crybo-rybo/scry/pull/131))
- **Repository.** `SECURITY.md` is removed.
  ([#127](https://github.com/crybo-rybo/scry/pull/127))

## Upgrade

Update FetchContent pins to `v0.7.0` or request
`find_package(scry 0.7.0 CONFIG REQUIRED)`. The generated `<scry/version.hpp>`
reports `0.7.0`.

**If you use `scry::testing`.** Change your tests to `ScriptedServer` with the
table above. The tests must be able to listen on 127.0.0.1.

**If you build with `SCRY_CLANG_TOOLING`, `SCRY_BUILD_FUZZERS`, or the `ci` or
`fuzz` preset.** Remove them. Use `scripts/lint.sh` for clang-tidy and the
`dev` preset for the corpus replays.

**If you compare the result of `Turn::cancel()` after you destroy the
`Harness`.** Expect false.

**All other consumers.** Rebuild. You do not need to change the source.

## Validation

Each change in this release landed through a pull request. Hosted CI gated each
pull request with GCC 16 on Ubuntu 24.04. It ran these legs:

- the format check, clang-tidy on the kernel, and the repository rules
- the `dev` build with warnings as errors and the complete `ctest` suite
- ASan with UBSan
- TSan.

The scripted server has regression tests for a client that does not read, and
the real-time retry tests check lower bounds and counts only. New public API has
`static_assert`s and a compiling example.

Scry is still pre-1.0. The API, the ABI, and the persisted conversation formats
can change between releases.
