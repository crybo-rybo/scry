# Scry v0.6.0

Scry v0.6.0 puts reflection at the center of the library. Tools are annotated
C++ functions, namespaces of them, or toolbox objects, registered with
`ToolRegistry::add()`, and a turn can end with a typed C++ value through
`ask<T>()` and `send<T>()`. One reflected codec now maps the message model, the
saved conversation, provider request bodies, and stream events. Underneath, the
code that parses untrusted bytes moves into a reflection-free C++23 kernel that
parses and writes JSON itself, so Glaze is no longer a dependency.

It is a minor release because it removes and renames tool registration API,
changes how two kinds of JSON number read, and appends members to `Completion`.

## Breaking changes

### Tool registration moves onto `ToolRegistry`

| Removed or renamed | Use instead |
|---|---|
| `scry::reflection::add<Args>(registry, metadata, handler)` | `registry.add<Args>(metadata, handler)` |
| `scry::reflection::ToolMetadata` | `scry::ToolMetadata` |
| `ToolRegistry::add(ToolDefinition, handler)`, both overloads | `ToolRegistry::add_dynamic(...)`, same arguments |

The tool value types (`ToolMetadata`, `ToolDefinition`, `ToolCallContext`,
`ToolHandler`, `ContextualToolHandler`) move to the new `<scry/tool.hpp>`, which
`<scry/tool_registry.hpp>` includes. `<scry/events.hpp>` no longer includes
`<scry/tool_registry.hpp>`.
([#119](https://github.com/crybo-rybo/scry/pull/119))

### JSON numbers and escapes

- A number with an exponent is a double even when whole: `1e2`, like `1.0`,
  reads as `JsonKind::number` and does not decode into a reflected integer
  member.
- `-0` is the double -0.0 and writes as `-0`. It used to read as the integer 0.
- `escape_json_string()` writes `\u00XX` with uppercase hexadecimal, as the
  canonical writer always has.
  ([#122](https://github.com/crybo-rybo/scry/pull/122))

### Layout changes

`Completion` appends `structured` and `answer_attempt_count`, so binary
consumers must be rebuilt.

## New

### Reflected tools

```cpp
class Greenhouse {  // a toolbox: each annotated member function is a tool
public:
  [[= scry::reflection::tool{"Open or close the vents"}]] Climate set_vents(bool open);
};
tools.add(std::make_shared<Greenhouse>());  // or tools.add(Greenhouse{})
tools.add<^^almanac>();                     // every tool function in a namespace
tools.add<^^to_fahrenheit>();               // one tool function
tools.add<ForecastArgs>({.name = "forecast", .description = "..."}, handler);
```

After an optional leading `const ToolCallContext&`, a tool function takes
nothing, one aggregate that is the argument object, or named parameters that
Scry synthesizes into one. Toolbox members may use an explicit object
parameter, `scry::reflection::name` overrides a tool's name, and handlers may
return `void` or `scry::Status`, which send `{}`. Each `add()` call registers
all of its tools or none. A declaration Scry cannot register fails to compile
with a message naming it and the reason. See `examples/toolbox.cpp`.
([#119](https://github.com/crybo-rybo/scry/pull/119))

### Typed completions

```cpp
struct Verdict {
  [[= scry::reflection::description{"Is the claim supported?"}]] bool supported{};
  std::string reason{};
};
auto verdict = harness.ask<Verdict>(conversation, "Is the moon made of cheese?");
// Result<Answered<Verdict>>: verdict->value and verdict->completion
```

A typed turn offers a `respond` tool whose schema is generated from the answer
type and requires a tool call. The answer is decoded strictly on the host
thread inside `update()`; a rejected one goes back to the model as a tool error
naming the field at fault and costs a tool round. Committed history holds the
question, any real tool rounds, and the answer's canonical JSON as text.

- `ask<T>()` blocks. `send<T>()` delivers the answer's JSON in
  `Completion::structured`, with attempts in `answer_attempt_count`.
- `send_structured()` and `send_and_wait_structured()` take a
  `ResponseFormat` for a schema known only at runtime;
  `scry::reflection::response_format<T>()` builds one from a type.
- `scry::testing` adds `anthropic_text_tool_stream` and
  `openai_text_tool_stream` for responses with prose before their tool calls.

See `examples/typed_answer.cpp`.
([#120](https://github.com/crybo-rybo/scry/pull/120))

### Reflected codec

- `<scry/annotations.hpp>` holds `description` (unchanged), `name`, `tag`,
  `tool`, `skip_null`, `emit_null`, and `ignore_unknown`.
- A `std::variant` of `tag`ged aggregates encodes and decodes by a `"type"`
  member, with an `anyOf` schema.
- `scry::reflection::decode<T>()` reads a `JsonView` or `Json` strictly. The
  `Encodable` and `Decodable` concepts add `scry::Json` (and `std::string_view`
  for encoding); `Toolbox` checks a toolbox class.
- `JsonView::to_json()` writes a viewed value's canonical text, and `Message`
  encodes and decodes directly.

See `examples/typed_values.cpp`.
([#117](https://github.com/crybo-rybo/scry/pull/117),
[#118](https://github.com/crybo-rybo/scry/pull/118))

## Fixes

- **Canonical numbers.** `1.0e19` canonicalized to `1E19` and then to
  `10000000000000000000`, and `-0.0` to `-0` and then `0`. With the number rules
  above, canonical text always writes back as itself.
- **Overflowing numbers.** JSON validation accepted `1e400`, which parsing
  rejected; it now accepts exactly what parsing does.
  ([#122](https://github.com/crybo-rybo/scry/pull/122))
- **`float` results.** A `float` in a reflected tool result reached the model
  as nine digits (`0.7F` as `0.699999988`); it is now the shortest spelling,
  `0.7`. ([#117](https://github.com/crybo-rybo/scry/pull/117))

## Behavior details

- **Wire and saved formats:** apart from the number rules, request bodies and
  `Conversation::to_json()` documents are byte-identical to v0.5.0's. A typed
  turn adds the response tool and a required `tool_choice`; a server that
  ignores it fails the turn with `protocol`.
- **`Conversation::from_json` diagnostics** name the JSON path at fault, such as
  `$.messages[0].role`. The category is unchanged.
- **OpenAI stream errors:** a chunk with an over-limit argument fragment and
  then a malformed member fails with `protocol`, not `resource_limit`.
  ([#118](https://github.com/crybo-rybo/scry/pull/118))
- **Registration reads the call site:** `add<^^namespace>()` registers the
  tools declared before the call, as that translation unit sees them.
- **`reflection::encode()`** is unconstrained: an unsupported type fails with a
  diagnostic rather than leaving overload resolution. Test types with
  `Encodable`.
- **Compile time:** `<scry/tool_registry.hpp>`, and so `<scry/harness.hpp>`,
  now include `<meta>` and the codec.

## Documentation

The README and `docs/architecture.md` lead with reflected tools, call the
explicit-schema path dynamic tools, and add typed completions, the reflected
codec, the JSON layer's contract, and the kernel split. The existing examples
and the showcase's NPC world use the new tool forms.

## Build and contributor tooling

- **No Glaze.** libcurl is the only library dependency, and configuring no
  longer fetches one. ([#122](https://github.com/crybo-rybo/scry/pull/122))
- **CMake 3.30**, the first release that knows GCC's C++26 mode. The declared
  3.28 never configured, and v0.5.0's documented 3.31 was Glaze's floor.
- **The kernel.** `src/kernel/` (JSON, SSE, retry arithmetic, transport, error
  factory) is compiled as C++23 without reflection and archived into
  `scry::scry`; `kernel.include-boundary` limits its includes. The rest of
  `src/` may use reflection. ([#116](https://github.com/crybo-rybo/scry/pull/116))
- **Tooling.** `SCRY_CLANG_TOOLING` builds the kernel alone for clang-tidy and
  the `sse`, `response_policy`, and new `json` libFuzzer targets. `anthropic`,
  `openai`, and `conversation` became GCC corpus replays, which the sanitizer
  legs run but nothing searches from
  ([#115](https://github.com/crybo-rybo/scry/issues/115)).
  `tests/fixtures/json/goldens.tar.xz` pins the JSON layer's acceptance
  boundary and canonical bytes.
- **Clang 21 for tooling.** The clang-tidy leg now uses the fuzz leg's Clang 21
  against libstdc++, so the kernel converts numbers with `std::from_chars`
  instead of its own decimal conversion. `SCRY_CLANG_TOOLING_LIBCXX` is gone;
  on macOS, use `llvm@21`.

## Upgrade

Update FetchContent pins to `v0.6.0` or request
`find_package(scry 0.6.0 CONFIG REQUIRED)`, and configure with CMake 3.30 or
newer. The generated `<scry/version.hpp>` reports `0.6.0`.

**If you call `scry::reflection::add`.** Write
`tools.add<Args>({.name = ..., .description = ...}, handler)` and use
`scry::ToolMetadata`. An annotated function or toolbox can often replace both
the struct and the lambda.

**If you register explicit-schema tools.** Rename `add` to `add_dynamic`.

**If you read JSON numbers or compare escaped text.** Read `1e2`-style and `-0`
values with `JsonView::number()`, and expect uppercase hexadecimal from
`escape_json_string()`.

**If you supplied a packaged Glaze.** Drop it.

**If you run clang-tidy or the fuzzers locally.** Use Clang 21 and drop
`-DSCRY_CLANG_TOOLING_LIBCXX=ON`.

**Everyone else.** Rebuild; no source changes are needed.

## Validation

Every change landed through a pull request gated by hosted CI on GCC 16 for
Linux and macOS: the core gate (lizard, the `ci` build with warnings as errors,
the complete `ctest` suite, a staged install, and a package consumer
registering every tool form), ASan with UBSan, TSan, clang-tidy over the
kernel, the kernel fuzz corpus replay, and the Doxygen site with the pinned
clang-format 18 check. Request bodies were pinned byte for byte before their
encoders changed, and a differential fuzzer ran the new JSON layer against
Glaze for 4.3 million executions without a divergence before Glaze was removed.
Diagnostics have compile-fail tests; new public API has `static_assert`s in
`tests/public_api_contract.cpp` and compiling examples.

Scry remains pre-1.0: API, ABI, and persisted conversation formats may change
between releases.
