# Scry v0.6.0

Scry v0.6.0 puts reflection at the center of the library. A tool can be an
annotated C++ function, a namespace of these functions, or a toolbox object.
You register each of these forms with `ToolRegistry::add()`. A turn can also
end with a typed C++ value through `ask<T>()` and `send<T>()`.

One reflected codec now maps the message model, the saved conversation, provider
request bodies, and stream events. Below this codec, the code that parses
untrusted bytes moves into a C++23 kernel that has no reflection. This kernel
parses and writes JSON itself, so Glaze is not a dependency now.

This is a minor release for three reasons. It removes and renames tool
registration API. It changes how two kinds of JSON number read. It also adds
members to the end of `Completion`.

## Breaking changes

### Tool registration moves onto `ToolRegistry`

| Removed or renamed | Use instead |
|---|---|
| `scry::reflection::add<Args>(registry, metadata, handler)` | `registry.add<Args>(metadata, handler)` |
| `scry::reflection::ToolMetadata` | `scry::ToolMetadata` |
| `ToolRegistry::add(ToolDefinition, handler)`, both overloads | `ToolRegistry::add_dynamic(...)`, same arguments |

The tool value types (`ToolMetadata`, `ToolDefinition`, `ToolCallContext`,
`ToolHandler`, `ContextualToolHandler`) move to the new `<scry/tool.hpp>`.
`<scry/tool_registry.hpp>` includes this header. `<scry/events.hpp>` does not
include `<scry/tool_registry.hpp>` now.
([#119](https://github.com/crybo-rybo/scry/pull/119))

### JSON numbers and escapes

- A number with an exponent is a double, also when its value is whole. Thus,
  `1e2` reads as `JsonKind::number`, as `1.0` does. It does not decode into a
  reflected integer member.
- `-0` is the double -0.0, and it writes as `-0`. Before, it read as the
  integer 0.
- `escape_json_string()` writes `\u00XX` with uppercase hexadecimal. The
  canonical writer always did this.
  ([#122](https://github.com/crybo-rybo/scry/pull/122))

### Layout changes

`Completion` adds `structured` and `answer_attempt_count` at the end. Thus, you
must rebuild binary consumers.

## New

### Reflected tools

```cpp
class Greenhouse {  // a toolbox: each annotated member function is a tool
public:
  [[= scry::reflection::tool{"Open or close the vents"}]] Climate set_vents(bool open);
};
tools.add(std::make_shared<Greenhouse>());  // or tools.add(Greenhouse{})
tools.add<^^almanac>();                     // every tool function in a namespace
tools.add<^^to_fahrenheit>();               // one tool function
tools.add<ForecastArgs>({.name = "forecast", .description = "..."}, handler);
```

A tool function can start with an optional `const ToolCallContext&`. After this
parameter, the function takes one of these:

- no arguments
- one aggregate that is the argument object
- named parameters. Scry makes one argument object from them.

Toolbox members can use an explicit object parameter. `scry::reflection::name`
overrides the name of a tool. A handler can return `void` or `scry::Status`.
These return types send `{}`. Each `add()` call registers all of its tools or
none of them. If Scry cannot register a declaration, the compilation fails. The
message identifies the declaration and gives the reason. See
`examples/toolbox.cpp`.
([#119](https://github.com/crybo-rybo/scry/pull/119))

### Typed completions

```cpp
struct Verdict {
  [[= scry::reflection::description{"Is the claim supported?"}]] bool supported{};
  std::string reason{};
};
auto verdict = harness.ask<Verdict>(conversation, "Is the moon made of cheese?");
// Result<Answered<Verdict>>: verdict->value and verdict->completion
```

A typed turn offers a `respond` tool. Scry generates the schema of this tool
from the answer type, and the turn requires a tool call. Scry decodes the answer
strictly on the host thread, inside `update()`. If Scry rejects an answer, it
sends the answer back to the model as a tool error. The error identifies the
field that is not correct. Each rejected answer uses one tool round. Committed
history holds the question, all real tool rounds, and the canonical JSON of the
answer as text.

- `ask<T>()` blocks. `send<T>()` gives the JSON of the answer in
  `Completion::structured`. It gives the number of attempts in
  `answer_attempt_count`.
- `send_structured()` and `send_and_wait_structured()` take a
  `ResponseFormat`. Use them for a schema that is known only at runtime.
  `scry::reflection::response_format<T>()` makes a `ResponseFormat` from a type.
- `scry::testing` adds `anthropic_text_tool_stream` and
  `openai_text_tool_stream`. Use them for responses that have prose before
  their tool calls.

See `examples/typed_answer.cpp`.
([#120](https://github.com/crybo-rybo/scry/pull/120))

### Reflected codec

- `<scry/annotations.hpp>` holds `description` (unchanged), `name`, `tag`,
  `tool`, `skip_null`, `emit_null`, and `ignore_unknown`.
- A `std::variant` of aggregates with a `tag` encodes and decodes by a `"type"`
  member. Its schema is an `anyOf` schema.
- `scry::reflection::decode<T>()` reads a `JsonView` or `Json` strictly.
- The `Encodable` and `Decodable` concepts add `scry::Json`. `Encodable` also
  adds `std::string_view`. `Toolbox` checks a toolbox class.
- `JsonView::to_json()` writes the canonical text of a viewed value. `Message`
  encodes and decodes directly.

See `examples/typed_values.cpp`.
([#117](https://github.com/crybo-rybo/scry/pull/117),
[#118](https://github.com/crybo-rybo/scry/pull/118))

## Fixes

- **Canonical numbers.** Before, `1.0e19` changed to `1E19` in canonical form,
  and then to `10000000000000000000`. `-0.0` changed to `-0`, and then to `0`.
  With the number rules above, canonical text always writes back as the same
  text.
- **Numbers that overflow.** Before, JSON validation accepted `1e400`, but
  parsing rejected it. Now validation accepts exactly the inputs that parsing
  accepts.
  ([#122](https://github.com/crybo-rybo/scry/pull/122))
- **`float` results.** Before, a `float` in a reflected tool result went to the
  model with nine digits (`0.7F` as `0.699999988`). Now Scry sends the shortest
  form, `0.7`. ([#117](https://github.com/crybo-rybo/scry/pull/117))

## Behavior details

- **Wire and saved formats:** request bodies and `Conversation::to_json()`
  documents are byte-identical to the v0.5.0 output. The only exception is the
  number rules. A typed turn adds the response tool and a required
  `tool_choice`. If a server ignores the `tool_choice`, the turn fails with
  `protocol`.
- **`Conversation::from_json` diagnostics** identify the JSON path of the
  problem, for example `$.messages[0].role`. The category does not change.
- **OpenAI stream errors:** a chunk can have an argument fragment that is
  larger than the limit, and then a malformed member. This chunk now fails with
  `protocol`, not `resource_limit`.
  ([#118](https://github.com/crybo-rybo/scry/pull/118))
- **Registration reads the call site:** `add<^^namespace>()` registers the tools
  that are declared before the call, as that translation unit sees them.
- **`reflection::encode()`** has no constraint. If a type is not supported, the
  compilation fails with a diagnostic. The overload does not leave overload
  resolution. To test a type, use `Encodable`.
- **Compile time:** `<scry/tool_registry.hpp>` now includes `<meta>` and the
  codec. Thus, `<scry/harness.hpp>` also includes them.

## Documentation

The README and `docs/architecture.md` now start with reflected tools. They call
the explicit-schema path "dynamic tools". They add typed completions, the
reflected codec, the contract of the JSON layer, and the kernel split. The
existing examples and the NPC world of the showcase use the new tool forms.

## Build and contributor tooling

- **No Glaze.** libcurl is the only library dependency. Configuration does not
  fetch a dependency now.
  ([#122](https://github.com/crybo-rybo/scry/pull/122))
- **CMake 3.30.** This is the first CMake release that knows the C++26 mode of
  GCC. The declared version, 3.28, never configured. The v0.5.0 documentation
  gave 3.31, because Glaze required it.
- **The kernel.** `src/kernel/` holds JSON, SSE, retry arithmetic, transport,
  and the error factory. The build compiles it as C++23 with no reflection and
  archives it into `scry::scry`. `kernel.include-boundary` limits its includes.
  The remaining code in `src/` can use reflection.
  ([#116](https://github.com/crybo-rybo/scry/pull/116))
- **Tooling.** `SCRY_CLANG_TOOLING` builds only the kernel. clang-tidy uses this
  build. The `sse`, `response_policy`, and new `json` libFuzzer targets also use
  it. `anthropic`, `openai`, and `conversation` are now GCC corpus replays. The
  sanitizer legs run these replays, but no leg searches from them
  ([#115](https://github.com/crybo-rybo/scry/issues/115)).
  `tests/fixtures/json/goldens.tar.xz` pins the acceptance boundary and the
  canonical bytes of the JSON layer.
- **Clang 21 for tooling.** The clang-tidy leg now uses the Clang 21 of the fuzz
  leg, against libstdc++. Thus, the kernel converts numbers with
  `std::from_chars`. It does not use its own decimal conversion now.
  `SCRY_CLANG_TOOLING_LIBCXX` is removed. On macOS, use `llvm@21`.

## Upgrade

Update FetchContent pins to `v0.6.0` or request
`find_package(scry 0.6.0 CONFIG REQUIRED)`. Configure with CMake 3.30 or newer.
The generated `<scry/version.hpp>` reports `0.6.0`.

**If you call `scry::reflection::add`.** Write
`tools.add<Args>({.name = ..., .description = ...}, handler)` and use
`scry::ToolMetadata`. Frequently, an annotated function or toolbox can replace
both the struct and the lambda.

**If you register explicit-schema tools.** Change `add` to `add_dynamic`.

**If you read JSON numbers or compare escaped text.** Read values such as `1e2`
and `-0` with `JsonView::number()`. Expect uppercase hexadecimal from
`escape_json_string()`.

**If you supplied a packaged Glaze.** Remove it.

**If you run clang-tidy or the fuzzers locally.** Use Clang 21, and remove
`-DSCRY_CLANG_TOOLING_LIBCXX=ON`.

**All other consumers.** Rebuild. You do not need to change the source.

## Validation

Each change in this release landed through a pull request. Hosted CI gated each
pull request with GCC 16 on Linux and macOS. It ran these legs:

- the core gate: lizard, the `ci` build with warnings as errors, the complete
  `ctest` suite, a staged install, and a package consumer that registers each
  tool form
- ASan with UBSan
- TSan
- clang-tidy on the kernel
- the kernel fuzz corpus replay
- the Doxygen site with the pinned clang-format 18 check.

Before their encoders changed, request bodies were pinned byte for byte. Before
the removal of Glaze, a differential fuzzer ran the new JSON layer against Glaze
for 4.3 million executions. It found no divergence. Diagnostics have
compile-fail tests. New public API has `static_assert`s in
`tests/public_api_contract.cpp` and compiling examples.

Scry is still pre-1.0. The API, the ABI, and the persisted conversation formats
can change between releases.
