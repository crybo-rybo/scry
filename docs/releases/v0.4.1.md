# Scry v0.4.1

Scry v0.4.1 reduces allocation, copying, and repeated scanning in tool turns,
callback delivery, JSON parsing, provider request encoding, and streamed
responses. It is a performance patch release with no public API changes.

## Performance

- **Tool turns:** canonicalize tool-call arguments in place and retain only
  pending call identifiers, avoiding copies of complete tool-call blocks while
  keeping dispatched arguments consistent with conversation history.
  ([#98](https://github.com/crybo-rybo/scry/pull/98))
- **Callback delivery:** remove redundant queue scans and lock acquisitions,
  borrow routes during dispatch, and move event payloads into their destinations.
  Rejected queue pushes no longer create unused accounting entries.
  ([#99](https://github.com/crybo-rybo/scry/pull/99))
- **JSON parsing:** validate and materialize JSON in one read instead of a
  validation pass followed by a second parse. Completion checks still reject
  truncated containers and trailing garbage, and whitespace-only input is
  rejected as an empty document.
  ([#100](https://github.com/crybo-rybo/scry/pull/100))
- **Provider requests:** encode Anthropic and OpenAI request bodies from typed
  wire structures that borrow strings and reuse stored canonical JSON, avoiding
  temporary JSON trees for conversation history and tool schemas on every
  attempt. Embedded payloads still receive a validation scan before encoding.
  ([#101](https://github.com/crybo-rybo/scry/pull/101))
- **Streaming:** reuse event buffers across SSE and provider decoding, accelerate
  newline searches, and avoid rescanning incomplete line prefixes. HTTP response
  handling retains the request identifier and retry metadata it uses instead of
  storing every response header.
  ([#102](https://github.com/crybo-rybo/scry/pull/102))

## Compatibility

Existing v0.4.0 consumers require no source changes. Provider wire formats,
callback ordering, resource limits, and cancellation behavior are preserved.
Regression coverage includes provider request fixtures, malformed JSON,
fragmented SSE input, queue accounting, and callback reentrancy.

The build requirements remain C++26 with GCC 16 reflection support, CMake 3.28
or newer, and libcurl 7.84 or newer. Scry remains pre-1.0; API, ABI, and persisted
conversation formats may change between releases.

## Upgrade

Update FetchContent pins to `v0.4.1` or request
`find_package(scry 0.4.1 CONFIG REQUIRED)`. The generated `<scry/version.hpp>`
reports `0.4.1`.
