# Scry v0.4.1

Scry v0.4.1 reduces allocation, copies, and repeated scans in these areas: tool
turns, callback delivery, JSON parsing, provider request encoding, and streamed
responses. This release is a performance patch release. It has no public API
changes.

## Performance

- **Tool turns:** Scry now canonicalizes tool-call arguments in place and keeps
  only the identifiers of pending calls. Thus, it does not copy complete
  tool-call blocks. The dispatched arguments stay consistent with the
  conversation history.
  ([#98](https://github.com/crybo-rybo/scry/pull/98))
- **Callback delivery:** This release removes redundant queue scans and lock
  acquisitions. Scry borrows routes during dispatch, and it moves event payloads
  into their destinations. A rejected queue push no longer creates an unused
  accounting entry.
  ([#99](https://github.com/crybo-rybo/scry/pull/99))
- **JSON parsing:** Scry now validates and materializes JSON in one read.
  Before, it did a validation pass and then a second parse. Completion checks
  still reject truncated containers and trailing garbage. Scry rejects input
  that has only whitespace as an empty document.
  ([#100](https://github.com/crybo-rybo/scry/pull/100))
- **Provider requests:** Scry now encodes Anthropic and OpenAI request bodies
  from typed wire structures. These structures borrow strings and reuse stored
  canonical JSON. Thus, Scry does not make temporary JSON trees for the
  conversation history and the tool schemas on each attempt. Embedded payloads
  still get a validation scan before Scry encodes them.
  ([#101](https://github.com/crybo-rybo/scry/pull/101))
- **Streaming:** Scry now reuses event buffers across SSE and provider decoding.
  It makes newline searches faster, and it does not scan incomplete line
  prefixes again. The code that handles HTTP responses keeps the request
  identifier and the retry metadata that it uses. It does not store every
  response header.
  ([#102](https://github.com/crybo-rybo/scry/pull/102))

## Compatibility

Current v0.4.0 consumers do not have to change their source. This release does
not change the provider wire formats, the callback order, the resource limits,
or the cancellation behavior. The regression coverage includes provider request
fixtures, malformed JSON, fragmented SSE input, queue accounting, and callback
reentrancy.

The build requirements do not change: C++26 with GCC 16 reflection support,
CMake 3.28 or newer, and libcurl 7.84 or newer. Scry is still pre-1.0. The API,
the ABI, and the formats for persisted conversations can change between
releases.

## Upgrade

Update FetchContent pins to `v0.4.1` or request
`find_package(scry 0.4.1 CONFIG REQUIRED)`. The generated `<scry/version.hpp>`
reports `0.4.1`.
