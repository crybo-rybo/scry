# Scry v0.5.0

Scry v0.5.0 adds an optional sampling seed for OpenAI-compatible servers. It also
fixes three bugs:

- Control characters caused invalid JSON.
- Reflected handlers that returned `Result<const T>` did not compile.
- A tool-admission hook that threw sent the model a text that was different from
  the documented text.

Clearer documentation also closes the remaining tool-boundary issues from the
pig-pen integration.

Internally, this release is a large simplification. The library, the tests, and
the build have about 2,500 fewer lines. No documented guarantee changes, except
for the few behavior details that this document lists below.

This is a minor release for two reasons. It removes three helpers from the
public `scry::testing` streams header. It also changes the layout of some public
types, so you must rebuild binary consumers.

## Breaking changes

### Three `scry::testing` stream helpers removed

`<scry/testing/streams.hpp>` does not declare these functions in `scry::testing`
now. Scry used them only inside the builders.
([#107](https://github.com/crybo-rybo/scry/pull/107))

| Removed | Use instead |
|---|---|
| `json_string(text)` | `scry::escape_json_string(text)` from `<scry/json.hpp>`, which `json_string` wrapped with no change |
| `anthropic_tool_block_events(index, block)` | `anthropic_tool_stream({...})` for a complete body |
| `openai_tool_call_entry(index, block)` | `openai_tool_stream({...})` for a complete body |

The frame parts that the builders share are now in
`scry::testing::stream_frames`. The documentation identifies this namespace as
internal, and it can change without notice.

### Layout changes

- `SamplingConfig` adds `seed` at the end, so the size of `Config` changes.
  Positional and designated initializers continue to compile. Structured
  bindings over `SamplingConfig` change arity.
- `Conversation` now holds its state through a `std::shared_ptr`. Before, it
  used a `std::unique_ptr`. `JsonView` now holds one aliasing `std::shared_ptr`,
  not a document pointer and a node pointer. The API does not show these two
  changes.

Each of these types is passed by value or is embedded in public types. Thus, you
must rebuild binary consumers.

## New

### Sampling seed

`SamplingConfig::seed` is an optional `std::uint32_t`. If the seed is set, the
OpenAI-compatible dialect sends it as the Chat Completions `seed` field. If the
seed is not set, the dialect omits it, so existing requests do not change. Each
request of a turn sends the same value, including retries and tool rounds.

The Anthropic Messages API has no seed. Thus, if the seed is set, the Anthropic
dialect rejects it during validation. It rejects disabled reasoning in the same
way. The dialect does not drop the seed, because then a host can believe that
its runs used the seed.

Scry sends the seed through and makes no promise about repeatability. The server
controls whether the same seed, model, prompt, and sampling values give the same
output again. The server does this only on a best-effort basis. This behavior
does not carry across models, servers, or server versions.

The field has 32 bits for two reasons. Each value fits in the seed range that
OpenAI-compatible servers accept. Each value also stays correct in JSON parsers
that read numbers as doubles.

```cpp
auto harness = scry::Harness::create({
    .base_url = "http://127.0.0.1:11434/v1",
    .model = "qwen3:8b",
    .dialect = scry::ProviderDialect::openai_compatible,
    .sampling = {.temperature = 0.8, .seed = 42},
});
```

The new `examples/seeded_trials.cpp` runs one prompt a number of times on a
local model with a fixed seed. It reports whether the answers were the same.
([#42](https://github.com/crybo-rybo/scry/issues/42),
[#112](https://github.com/crybo-rybo/scry/pull/112))

## Fixes

- **JSON control characters.** Each JSON write now escapes a control character
  with no short escape as `\u00XX`. The short escapes are `\b`, `\f`, `\n`,
  `\r`, and `\t`. Before, Scry wrote invalid JSON for tool arguments, text, or
  object keys that contained a byte such as `\x01` or an ANSI escape. With this
  invalid JSON, it was possible that a provider rejected the request. It was
  also possible that `Conversation::to_json()` failed on a history that
  `Conversation::from_json()` accepted immediately before. The scheduled
  conversation fuzzer found this bug. The input that caused the crash is now a
  regression test and part of the fuzz corpus.
  ([#107](https://github.com/crybo-rybo/scry/pull/107),
  [#108](https://github.com/crybo-rybo/scry/issues/108))
- **`Result<const T>` reflected handlers.** A reflected handler that returned
  `scry::Result<const T>` satisfied `ToolHandlerFor`, but it did not compile
  inside the library. Now the handler registers, and Scry encodes its value.
  ([#107](https://github.com/crybo-rybo/scry/pull/107))
- **Admission hooks that throw.** The documentation of
  `TurnCallbacks::on_tool_request` says that Scry treats a hook that throws
  exactly like a handler that throws. But from v0.4.0, the model got
  `tool handler threw an exception` for a hook. For a handler, the model got
  `tool handler returned an error`. Now the two cases send
  `tool handler returned an error`.

## Behavior details

- **SSE:** a blank line that ends with a lone CR now dispatches its event in the
  chunk that carries the line. Before, the dispatch waited for the next byte.
- **`Conversation::from_json` diagnostics:** error messages now identify the
  specific problem. Before, they gave only `invalid prompt or messages`. The
  category does not change.
- **OpenAI stream errors:** if an error `type` or `code` is literally
  `unknown_error`, Scry now reports that token. Before, Scry treated that value
  as absent.
  ([#107](https://github.com/crybo-rybo/scry/pull/107))

## Documentation

- The `ToolHandler` comment and `docs/architecture.md` now clearly state what
  argument validation covers. Scry makes sure that tool arguments parse into a
  JSON object. It does not make sure that they match the registered schema. The
  explicit-schema handler is responsible for that check. We recommend that this
  handler rejects with `scry::tool_error()`, so that the model learns what to
  correct. The `echo` handler of the canonical example now does this.
  Before, it rejected with a plain `scry::Error`, so the model got only
  `tool handler returned an error`.
  ([#39](https://github.com/crybo-rybo/scry/issues/39),
  [#112](https://github.com/crybo-rybo/scry/pull/112))
- Before, `Error::model_message` and `docs/architecture.md` said that Scry uses
  its fixed diagnostic for a `model_message` that is too large. Now they say
  that Scry replaces it with the general text `tool execution failed`. The code
  always did this.
- The README now starts with what Scry does. Then it gives the requirements and
  the installation. ([#106](https://github.com/crybo-rybo/scry/pull/106))
- The README and the contributing guide now give the real CMake requirement:
  3.31. The reason is that the Glaze revision that Scry fetches requires 3.31.
  The build files of Scry continue to accept 3.28 when CMake finds a packaged
  Glaze. The Linux setup now does not install CMake 3.28 from Ubuntu 24.04,
  because the fetched Glaze rejects that version. The requirement is the same
  as in v0.4.1, but the v0.4.1 notes gave 3.28.
- This release audited the source comments in the library, the public headers,
  the tests, and the build against the current code. Some comments described
  earlier implementations or recorded old decisions that later decisions
  replaced. These comments now state the current constraint. The audit also
  corrected the comments that did not agree with the code. These include the
  comments on the public `JsonKind` integer kinds and on
  `ReasoningMode::disabled` for the Anthropic dialect.

## Build and contributor tooling

- This release removes the `SCRY_FORMAT_CHECK` and `SCRY_TIDY_LIBCXX` script
  environment variables and the `SCRY_FUZZ_RUNS` CMake option.
  `scripts/ci-local.sh` does not run the format check now.
  `scripts/preflight.sh` and the documentation leg run it. To analyze against
  libc++, pass `-DSCRY_CLANG_TOOLING_LIBCXX=ON` to `scripts/ci-tidy.sh`. On the
  `fuzz` preset, `ctest` replays the checked-in corpus one time. It does not run
  a fixed number of iterations.
  ([#107](https://github.com/crybo-rybo/scry/pull/107))
- Scheduled CI retries its toolchain installs up to three times.
  ([#111](https://github.com/crybo-rybo/scry/pull/111))

## Upgrade

Update FetchContent pins to `v0.5.0` or request
`find_package(scry 0.5.0 CONFIG REQUIRED)`. The generated `<scry/version.hpp>`
reports `0.5.0`.

**If a test calls `scry::testing::json_string`.** Replace it with
`scry::escape_json_string`. The output is the same.

**If a test calls `anthropic_tool_block_events` or `openai_tool_call_entry`.**
Build the complete body with `anthropic_tool_stream` or `openai_tool_stream`
instead.

**All other consumers.** Rebuild. You do not need to change the source. Provider
wire formats do not change, except for the optional `seed` field and the correct
escape of control characters.

## Validation

Each change in this release landed through a pull request. Hosted CI gated each
pull request with GCC 16 on Linux and macOS. It ran these legs:

- the core gate: lizard, the `ci` build with warnings as errors, the complete
  `ctest` suite, a staged install, and the installed-package consumer
- ASan with UBSan
- TSan
- the clang-tooling build and the clang-tidy leg
- the fuzz corpus replay
- the Doxygen API site with the pinned clang-format 18 check.

Each bug fix landed with a regression test first. The new public field landed
with `static_assert`s in `tests/public_api_contract.cpp` and a compiling example.

Scry is still pre-1.0. The API, the ABI, and the persisted conversation formats
can change between releases.
