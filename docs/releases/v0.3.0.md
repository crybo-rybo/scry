# Scry v0.3.0

Scry v0.3.0 makes C++26 reflection a core part of the library. Before, it was
an optional component. This release also closes the API gaps that a foundation
audit found. It removes the machinery that cost more than the protection that
it gave. The library now has one target, one compiler, and three documents.

## Breaking changes

### GCC 16 or newer is necessary

C++26 reflection (P2996) is part of the core public API. `<scry/scry.hpp>`
includes `<scry/reflection.hpp>`. Reflected registration is the primary method
to declare a tool. Every consumer build must use `-std=c++26 -freflection`. At
this time, GCC 16 is the only compiler that supplies these flags. There is no
reflection-OFF C++23 consumer build. Scry does not support Clang and MSVC until
they ship P2996.

The implementation under `src/` intentionally stays portable C++23 and has no
reflection syntax. This lets clang-tidy and libFuzzer continue to work. The new
`SCRY_CLANG_TOOLING=ON` option selects exactly that build. This build uses a
Clang-family compiler, C++23, no `-freflection`, and no examples. Of the tests,
it builds only the fuzz targets. The `SCRY_CLANG_TOOLING_LIBCXX=ON` option is
for hosts with a libstdc++ that is newer than the tooling compiler can parse.
Scry does not support these two builds as consumer builds.

### One target, one package

This release removes the `scry::reflection` target and the `reflection` package
component. All of the library is now `scry::scry`:

```cmake
find_package(scry 0.3.0 CONFIG REQUIRED)
target_link_libraries(app PRIVATE scry::scry)
```

Remove `COMPONENTS reflection` from `find_package`. Replace each
`scry::reflection` link with `scry::scry`. The `scry::reflection` *namespace*
does not change. This release removes only the CMake target.

### Removed build options

This release removes these build options: `SCRY_ENABLE_REFLECTION`,
`SCRY_ENABLE_LOGGING`, `SCRY_BUILD_BENCHMARKS`, `SCRY_BUILD_IMGUI_SHOWCASE`,
`SCRY_BUILD_LOCAL_MODEL_SMOKE`, and `SCRY_USE_LIBCXX`. It also removes the
`dev-logging`, `profile`, `reflection-gcc16`, `showcase`, and
`nightly-local-model` presets. If you pass a removed option, it does not cause
a problem, but it has no effect. These presets stay: `dev`, `ci`, `asan`,
`tsan`, and `fuzz`.

The minimum CMake version is now 3.28. Before, it was 3.25. This change makes
sure that the `EXCLUDE_FROM_ALL` option of `FetchContent` operates as the
packaging audit assumes.

### `TransportTimeouts` adds `idle` and makes `transfer` optional

`TransportTimeouts::transfer` is now `std::optional<std::chrono::milliseconds>`.
By default, it has no value. A new `idle` field has a default of 120 seconds:

```cpp
struct TransportTimeouts {
  std::chrono::milliseconds connect{10'000};
  std::chrono::milliseconds idle{120'000};
  std::optional<std::chrono::milliseconds> transfer{};
  std::chrono::milliseconds shutdown{2'000};
};
```

The idle bound is the default liveness guarantee. It fails a transfer that
stays silent for that time. This includes the wait for the first byte. Thus,
the time of silence limits a slow local model, not the total duration. A v0.2.0
consumer that set `.transfer = X` still compiles. But in most cases, we
recommend that you move that value to `.idle`. If your aggregate initialization
used the old field order, update it.

### `ErrorCategory::invalid_argument`

This release inserts a new enumerator after `invalid_state`. Thus, the
underlying value of each enumerator after it increases by one. Failures of
argument validation now report `invalid_argument`, not `invalid_state`. These
failures include an empty tool name, a duplicate name, a bad schema, and an
empty user message. Recompile against the new header. Update all code that
switches on the numeric values or persists them.

### `Error::http_status`

This release inserts a `std::uint16_t http_status` member after `retryable`.
This member uses padding that was already there. Thus, `sizeof(Error)` does not
change, but positional aggregate initialization breaks. Designated initializers
in declaration order continue to work:

```cpp
scry::Error error{
    .category = scry::ErrorCategory::network,
    .retryable = true,
    .message = "request failed",
};
```

### The compile-time logging mode is removed

This release removes `SCRY_ENABLE_LOGGING`, the internal `SCRY_LOG` macro,
`src/core/log.*`, and the `SCRY_LOG_FILE` environment variable. Scry never
wrote a log file that the host did not ask for. No public logging surface
replaces this mode. The runtime still shows diagnostics through `Error` and the
terminal channel of the turn.

### `<scry/version.hpp>` is generated

CMake generates the version header from the `project(VERSION ...)` call in
`CMakeLists.txt`. This call is now the only location of the release number. The
repository no longer tracks the header. For consumers of the installed or
exported package, nothing changes. In-tree builds must configure before the
header exists.

## Added

- **`scry::JsonView` and `scry::escape_json_string()`.** `Json` was a bare
  string with no read API. `JsonView` gives the value kind, scalar accessors,
  the array index, `find()`, `at()`, and ordered `key_at()`. It operates on one
  shared, immutable, canonical document. `escape_json_string()` quotes one
  string for a result that you build by hand. A third-party parser is not
  necessary for either of them.
- **The public message model.** `Role`, `TextBlock`, `ToolCallBlock`,
  `ToolResultBlock`, `ContentBlock`, and `Message` are public in
  `<scry/message.hpp>`. The internal model re-exports this same family.
  `Conversation::messages()`, `system_prompt()`, and `busy()` expose the
  committed state directly. Thus, a chat UI renders the history and does not
  have to keep a copy of it.
- **`Turn::finished()` and `Turn::disconnect()`.** `finished()` shows if Scry
  delivered the terminal outcome. Thus, a poll loop can stop on the turn itself.
  `disconnect()` clears all callbacks for a live turn. The turn continues to run
  and still commits or rolls back its Conversation. But nothing more gets to the
  host.

  `disconnect()` is the complement of `cancel()`. `cancel()` stops the work and
  still reports it. `disconnect()` keeps the work and stops the reports. Before,
  each host invented a weak-pointer-plus-generation scheme. `disconnect()`
  removes the necessity for that scheme.
- **`Harness::validate(const Config&)`, `Harness::cancel(TurnId)`, and
  `Harness::disconnect(TurnId)`.** `validate` runs exactly the create-time
  configuration checks. It does not initialize libcurl or start a worker. Thus,
  a settings dialog can report problems first. The other two functions are the
  handle operations, but they use an identifier to find the turn.
- **`ToolRegistry::contains()` and `names()`.**
- **`ToolCall::result` and `ToolCall::is_error`.** The `on_tool_call` observer
  now carries the canonical JSON result that Scry gives back to the model. It
  also tells if that result was an error. Thus, a UI can show what a tool
  returned.
- **`Config::ca_bundle_path`, `Config::proxy`, `Config::extra_headers`, and
  `scry::HttpHeader`.** A private or corporate CA is now reachable, and you do
  not have to disable TLS verification. The names and values of extra headers
  go through the same header-injection validation as the headers of Scry. If a
  name collides with a header that Scry manages, Scry rejects it with
  `invalid_config`.
- **An `update()` progress guarantee.** Before each call examines the time
  budget, it ingests at least one queued event. If a deliverable callback exists
  and `max_callbacks` allows it, the call also delivers at least one callback
  before that check. Now a very small or already expired budget makes the pump
  slower, but it does not starve the pump.
- **Two more fuzz targets, replayed per commit.** `scry_response_policy_fuzz`
  covers the accounting of HTTP response headers and bodies.
  `scry_conversation_fuzz` covers `Conversation::from_json` with a canonical
  round-trip assertion. Now all five targets build and replay their checked-in
  seed corpus on each pull request. They do this under ASan and non-recovering
  UBSan. Thus, a target cannot silently break between long runs.
- **A release workflow.** When you push a `v*` tag, the workflow first runs the
  core gate again against the tagged tree. Then it builds the API site. Then it
  publishes the GitHub release from `docs/releases/<tag>.md`.
  `./scripts/check-release-tag.sh` refuses a tag that does not name the
  `project()` version.

## Changed

- Each Harness now seeds its retry jitter independently. Before, the jitter was
  a hash of the turn id and the attempt. Thus, a fleet no longer retries in
  lockstep. Only the internal test seam can inject a seed.
- UBSan is now fatal. The sanitizer build adds `-fno-sanitize-recover=undefined`,
  and a probe test proves this. Thus, undefined behavior fails the leg. Before,
  it printed a message and exited with zero.
- For the OpenAI-compatible dialect, you can leave `SamplingConfig::max_tokens`
  unset. In that case, Scry does not put the field in the request, and the
  server default applies. For the Anthropic dialect, the field is still
  necessary.
- Scry no longer loses a non-2xx response body. The transport keeps at most
  8 KiB of the body. It uses this part to extract the provider's own
  `error.type` or `error.code` token. This token goes to `Error::provider_detail`
  under the dialect namespace (for example, `anthropic:not_found_error`). The
  status goes to `Error::http_status`.
- The Dear ImGui and NPC showcase moved to `extras/showcase/`. It is a separate
  CMake project, and the root build never configures it.
  `./scripts/ci-showcase.sh` configures it directly. Then the script audits the
  installed package for leaks.
- Each CI leg is now one script under `scripts/`. Both the workflows and
  `preflight.sh` call this script. Thus, a local gate and its hosted twin cannot
  drift. This release pins hosted actions to commit SHAs and configures
  Dependabot. It also adds `SECURITY.md`. If the host does not have a toolchain,
  preflight reports that toolchain as unavailable. But preflight still reports
  real tool failures as failures.
- This release updates the dependency pins of the release to Glaze 8.3.0,
  Catch2 3.16.0, Dear ImGui 1.92.9b, lizard 1.24.0, Ollama 0.33.2, and
  `actions/checkout` 7.0.1.
- This release combines the documentation from twenty-two files into three:
  `README.md`, `docs/architecture.md`, and `docs/contributing.md`. Plain
  guarantee bullets and a deliberate-simplifications table inside
  `docs/architecture.md` replace the numbered RFC-2119 requirements register,
  its verification map, and the evolution register. The foundation audit stays
  in the repository as `docs/audits/2026-09-fable.md`.
- This release removes the profiling apparatus: `benchmarks/`, `scripts/perf-*`,
  Google Benchmark, and the performance workflow. The apparatus was opt-in. By
  the project's own policy, it was not eligible as evidence. It was also larger
  than what it protected. `b1724fe` is the last commit that contained it.

## Fixed

- If you call `disconnect()` from inside `on_text_delta` or `on_tool_call`, Scry
  no longer destroys the callback closure while it still runs. Scry now removes
  the callback only after the current invocation unwinds. This is also true
  when it unwinds through an exception.
- The JSON parser now validates the complete input before it decodes the input.
  It now rejects truncated objects and arrays, trailing garbage, and a second
  concatenated document. Before, it accepted them at the end of a
  non-null-terminated buffer.
- Values of extra HTTP headers reject each control byte other than tab. This
  includes an embedded NUL. Without this check, libcurl silently truncates such
  a header and sends it.
- The HTTP response-policy fuzzer now keeps its chunk selector out of the parsed
  payload. It varies the chunk boundaries, as its design intends. It also stops
  the header parse at the blank line, so that JSON response bodies get coverage.
- Before, `scry::UniqueFunction` rejected a non-void callable in a void
  signature with a hard compile error. Thus, a lambda that returned a value was
  not valid as an `on_text_delta`. It now invokes through `std::invoke_r`. It
  also treats a null function pointer as an empty wrapper, not as a non-empty
  one.
- Before, the loopback test server stopped in this sequence: shutdown, join,
  close. On macOS, `shutdown` on a listening socket does not wake `accept`.
  Thus, if curl never connected in a test, that test became a silent ctest
  timeout.
- Before, `cancel-in-progress` applied to pushes on `main`. Thus, a merge
  directly after another merge was able to cancel the run of the previous merge.
  Then `main` had commits with no completed CI. Now `cancel-in-progress` applies
  only to pull requests.
- The path filter of the reflection gate did not include the core public headers
  or any of `src/`. Thus, a core change that broke the reflected surface was
  able to merge without a test. The filter is not relevant now, because
  reflection is core and every leg builds it.
- `JsonView::parse` now parses the document in place. This fixes a GCC 14
  `-Wmaybe-uninitialized` false positive in `JsonView::parse`.
- A retry-wait lambda shadowed an enclosing name.

## Upgrade

1. Install GCC 16 or newer. Build with `-std=c++26 -freflection`.
2. If you vendor Scry, increase your CMake minimum to 3.28.
3. Change the call to `find_package(scry 0.3.0 CONFIG REQUIRED)`. Remove
   `COMPONENTS reflection`. Link `scry::scry` in place of `scry::reflection`.
4. Delete all `SCRY_ENABLE_REFLECTION`, `SCRY_ENABLE_LOGGING`,
   `SCRY_BUILD_BENCHMARKS`, `SCRY_BUILD_IMGUI_SHOWCASE`,
   `SCRY_BUILD_LOCAL_MODEL_SMOKE`, and `SCRY_USE_LIBCXX` settings. Remove all
   references to the removed presets.
5. If a hard cap on one transfer is not necessary, move the
   `TransportTimeouts::transfer` value to `idle`. Update aggregate initializers
   for the new field order and for `Error::http_status`.
6. Recompile all code that switches on `ErrorCategory`. Expect `invalid_argument`
   where argument validation reported `invalid_state` before.
7. Remove all code that handles `SCRY_LOG_FILE`.
8. Rebuild the dependents. This release changes the layout and the source.

Scry is still pre-1.0. The API, the ABI, and the formats for persisted
conversations can change between releases.
