# Scry v0.3.0

Scry v0.3.0 makes C++26 reflection a core part of the library rather than an
optional component, closes the API gaps a foundation audit found, and removes
the machinery that was costing more than it protected. The library is now one
target, one compiler, and three documents.

## Breaking changes

### GCC 16 or newer is required

C++26 reflection (P2996) is part of the core public API: `<scry/scry.hpp>`
includes `<scry/reflection.hpp>`, and reflected registration is the primary way
to declare a tool. Every consumer build needs `-std=c++26 -freflection`, which
GCC 16 is currently the only compiler to provide. There is no reflection-OFF
C++23 consumer build, and Clang and MSVC are unsupported until they ship P2996.

The implementation under `src/` deliberately stays portable C++23 with no
reflection syntax, which is what keeps clang-tidy and libFuzzer working. The new
`SCRY_CLANG_TOOLING=ON` option selects exactly that build — a Clang-family
compiler, C++23, no `-freflection`, no examples, and only the fuzz targets among
the tests — with `SCRY_CLANG_TOOLING_LIBCXX=ON` for hosts whose libstdc++ is
newer than the tooling compiler can parse. Neither is a supported consumer build.

### One target, one package

The `scry::reflection` target and the `reflection` package component are gone.
Everything is `scry::scry`:

```cmake
find_package(scry 0.3.0 CONFIG REQUIRED)
target_link_libraries(app PRIVATE scry::scry)
```

Drop `COMPONENTS reflection` from `find_package` and replace every
`scry::reflection` link with `scry::scry`. The `scry::reflection` *namespace* is
unchanged; only the CMake target went away.

### Removed build options

`SCRY_ENABLE_REFLECTION`, `SCRY_ENABLE_LOGGING`, `SCRY_BUILD_BENCHMARKS`,
`SCRY_BUILD_IMGUI_SHOWCASE`, `SCRY_BUILD_LOCAL_MODEL_SMOKE`, and
`SCRY_USE_LIBCXX` no longer exist, and neither do the `dev-logging`, `profile`,
`reflection-gcc16`, `showcase`, and `nightly-local-model` presets. Passing a
removed option is harmless but has no effect. The remaining presets are `dev`,
`ci`, `asan`, `tsan`, and `fuzz`.

The minimum CMake version is now 3.28, up from 3.25, so `FetchContent`'s
`EXCLUDE_FROM_ALL` behaves as the packaging audit assumes.

### `TransportTimeouts` gained `idle` and made `transfer` optional

`TransportTimeouts::transfer` is now `std::optional<std::chrono::milliseconds>`
and unset by default, and a new `idle` field defaults to 120 seconds:

```cpp
struct TransportTimeouts {
  std::chrono::milliseconds connect{10'000};
  std::chrono::milliseconds idle{120'000};
  std::optional<std::chrono::milliseconds> transfer{};
  std::chrono::milliseconds shutdown{2'000};
};
```

The idle bound is the default liveness guarantee: it fails a transfer that stays
silent that long, including while waiting for the first byte, so a slow local
model is limited by silence rather than by total duration. A v0.2.0 consumer that
set `.transfer = X` still compiles, but should usually move that value to
`.idle`. Aggregate initialization that relied on the old field order must be
updated.

### `ErrorCategory::invalid_argument`

A new enumerator is inserted after `invalid_state`, so every later enumerator's
underlying value shifts by one. Argument-validation failures — an empty tool
name, a duplicate name, a bad schema, an empty user message — now report
`invalid_argument` instead of `invalid_state`. Recompile against the new header
and update any code that switched on numeric values or persisted them.

### `Error::http_status`

A `std::uint16_t http_status` member is inserted after `retryable`, occupying
padding that already existed, so `sizeof(Error)` is unchanged but positional
aggregate initialization breaks. Designated initializers in declaration order
keep working:

```cpp
scry::Error error{
    .category = scry::ErrorCategory::network,
    .retryable = true,
    .message = "request failed",
};
```

### The compile-time logging mode is removed

`SCRY_ENABLE_LOGGING`, the internal `SCRY_LOG` macro, `src/core/log.*`, and the
`SCRY_LOG_FILE` environment variable are gone. Scry never wrote a log file the
host did not ask for, and no public logging surface replaces it; the runtime
still surfaces diagnostics through `Error` and the turn's terminal channel.

### `<scry/version.hpp>` is generated

The version header is generated from the `project(VERSION ...)` call in
`CMakeLists.txt`, which is now the only place the release number lives, and is no
longer tracked in the repository. Consumers of the installed or exported package
see no difference; in-tree builds must configure before the header exists.

## Added

- **`scry::JsonView` and `scry::escape_json_string()`.** `Json` was a bare string
  with no read API. `JsonView` gives value kind, scalar accessors, array index,
  `find()`, `at()`, and ordered `key_at()` over one shared immutable canonical
  document, and `escape_json_string()` quotes one string for a hand-built result.
  Neither needs a third-party parser.
- **The public message model.** `Role`, `TextBlock`, `ToolCallBlock`,
  `ToolResultBlock`, `ContentBlock`, and `Message` are public in
  `<scry/message.hpp>`, and the internal model is that same family re-exported.
  `Conversation::messages()`, `system_prompt()`, and `busy()` expose committed
  state directly, so a chat UI renders history instead of mirroring it.
- **`Turn::finished()` and `Turn::disconnect()`.** `finished()` reports whether
  the terminal outcome was delivered, so a poll loop can stop on the turn itself.
  `disconnect()` clears every callback for a live turn: the turn keeps running and
  still commits or rolls back its Conversation, but nothing further reaches the
  host. It is the complement of `cancel()` — cancel stops the work and still
  reports it, disconnect keeps the work and stops the reporting — and it removes
  the need for the weak-pointer-plus-generation scheme every host was inventing.
- **`Harness::validate(const Config&)`, `Harness::cancel(TurnId)`, and
  `Harness::disconnect(TurnId)`.** `validate` runs exactly the create-time
  configuration checks without initializing libcurl or starting a worker, so a
  settings dialog can report problems first. The other two are the handle
  operations addressed by identifier.
- **`ToolRegistry::contains()` and `names()`.**
- **`ToolCall::result` and `ToolCall::is_error`.** The `on_tool_call` observer
  now carries the canonical JSON result handed back to the model and whether it
  was an error, so a UI can show what a tool returned.
- **`Config::ca_bundle_path`, `Config::proxy`, `Config::extra_headers`, and
  `scry::HttpHeader`.** A private or corporate CA is now reachable without
  disabling TLS verification. Extra header names and values pass the same
  header-injection validation as Scry's own, and a name colliding with a
  Scry-managed header is rejected with `invalid_config`.
- **An `update()` progress guarantee.** Every call ingests at least one queued
  event and, where a deliverable callback exists and `max_callbacks` permits,
  delivers at least one callback before the time budget is consulted. A tiny or
  already-expired budget now slows the pump instead of starving it.
- **Two more fuzz targets, replayed per commit.** `scry_response_policy_fuzz`
  covers HTTP response-header and body accounting, and `scry_conversation_fuzz`
  covers `Conversation::from_json` with a canonical round-trip assertion. All five
  targets now build and replay their checked-in seed corpus on every pull request
  under ASan and non-recovering UBSan, so a target cannot rot between long runs.
- **A release workflow.** Pushing a `v*` tag re-runs the core gate against the
  tagged tree, builds the API site, and publishes the GitHub release from
  `docs/releases/<tag>.md`. `./scripts/check-release-tag.sh` refuses a tag that
  does not name the `project()` version.

## Changed

- Retry jitter is seeded independently per Harness instead of being a hash of the
  turn id and attempt, so a fleet no longer retries in lockstep. Seed injection
  stays confined to the internal test seam.
- UBSan is now fatal. The sanitizer build adds `-fno-sanitize-recover` and sets
  `halt_on_error`, so undefined behavior fails the leg instead of printing and
  exiting zero.
- `SamplingConfig::max_tokens` may be left unset for the OpenAI-compatible
  dialect, in which case the field is omitted from the request and the server
  default applies. The Anthropic dialect still requires it.
- A non-2xx response body no longer vanishes. The transport retains at most 8 KiB
  of it to extract the provider's own `error.type` or `error.code` token, which
  reaches `Error::provider_detail` under the dialect namespace
  (`anthropic:not_found_error`), alongside the status in `Error::http_status`.
- The Dear ImGui and NPC showcase moved to `extras/showcase/` as its own CMake
  project that the root build never configures; `./scripts/ci-showcase.sh`
  configures it directly and then audits the installed package for leaks.
- Every CI leg is now one script under `scripts/` that both the workflows and
  `preflight.sh` call, so a local gate and its hosted twin cannot drift. Hosted
  actions are pinned to commit SHAs, Dependabot is configured, and `SECURITY.md`
  exists.
- Documentation is consolidated from twenty-two files into three: `README.md`,
  `docs/architecture.md`, and `docs/contributing.md`. The numbered RFC-2119
  requirements register, its verification map, and the evolution register are
  replaced by plain guarantee bullets and a deliberate-simplifications table
  inside `docs/architecture.md`. The foundation audit is retained as
  `docs/audits/2026-09-fable.md`.
- The profiling apparatus — `benchmarks/`, `scripts/perf-*`, Google Benchmark,
  and the performance workflow — is removed. It was opt-in and
  evidence-ineligible by the project's own policy, and larger than what it
  protected. `b1724fe` is the last commit that contained it.

## Fixed

- `scry::UniqueFunction` rejected a non-void callable in a void signature with a
  hard compile error, so a lambda returning a value could not be an
  `on_text_delta`. It now invokes through `std::invoke_r` and treats a null
  function pointer as an empty wrapper rather than a non-empty one.
- The loopback test server tore down as shutdown, join, close. On macOS,
  `shutdown` on a listening socket does not wake `accept`, so a test where curl
  never connected became a silent ctest timeout.
- `cancel-in-progress` applied to pushes on `main`, so back-to-back merges could
  cancel the previous merge's run and leave `main` carrying commits with no
  completed CI. It is now limited to pull requests.
- The reflection gate's path filter omitted the core public headers and all of
  `src/`, so a core change that broke the reflected surface could merge untested.
  The filter is moot now that reflection is core and every leg builds it.
- A GCC 14 `-Wmaybe-uninitialized` false positive in `JsonView::parse` is fixed by
  parsing the document in place.
- A retry-wait lambda shadowed an enclosing name.

## Upgrade

1. Install GCC 16 or newer and build with `-std=c++26 -freflection`.
2. Raise your CMake minimum to 3.28 if you vendor Scry.
3. Change `find_package(scry 0.3.0 CONFIG REQUIRED)`, drop `COMPONENTS
   reflection`, and link `scry::scry` in place of `scry::reflection`.
4. Delete any `SCRY_ENABLE_REFLECTION`, `SCRY_ENABLE_LOGGING`,
   `SCRY_BUILD_BENCHMARKS`, `SCRY_BUILD_IMGUI_SHOWCASE`,
   `SCRY_BUILD_LOCAL_MODEL_SMOKE`, or `SCRY_USE_LIBCXX` settings, and stop
   referencing the removed presets.
5. Move any `TransportTimeouts::transfer` value to `idle` unless you really want
   a hard cap on one transfer, and update aggregate initializers for the new field
   order and for `Error::http_status`.
6. Recompile everything that switches on `ErrorCategory`, and expect
   `invalid_argument` where argument validation previously reported
   `invalid_state`.
7. Remove any `SCRY_LOG_FILE` handling.
8. Rebuild dependents: this release changes layout as well as source.

Scry remains pre-1.0: API, ABI, and persisted conversation formats may change
between releases.
