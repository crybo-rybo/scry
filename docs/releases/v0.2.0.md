# Scry v0.2.0

Scry v0.2.0 reduces allocation pressure in accepted turns and in streaming
decoders. It adds a reproducible profiling workflow. It also makes the
arithmetic for retry deadlines more robust. The increase of the minor version
shows a source and ABI break in the public `scry::Error` aggregate. This
release also removes a constant that gave no information from the experimental
reflection component.

## Breaking changes

### `scry::Error` member order

The members of `scry::Error` now have this declaration order:

1. `category`
2. `retryable`
3. `attempt`
4. `message`
5. `provider_detail`
6. `retry_after`
7. `turn_id`
8. `provider_request_id`

This release puts the scalar fields together. This reduces the padding in each
error that is carried by value. C++ designated initializers must follow the
declaration order. Thus, consumers that initialize the fields in the v0.1.x
order must reorder them. Also update positional aggregate initialization.
Rebuild binary consumers for the new layout. We recommend designated
initialization in the new order:

```cpp
scry::Error error{
    .category = scry::ErrorCategory::network,
    .retryable = true,
    .attempt = 2,
    .message = "request failed",
};
```

`scry::ErrorCategory` itself does not change. Its enumerators and their
underlying numeric values keep the v0.1.x order.

### Reflection capability constant removed

This release removes the experimental `scry::reflection::enabled` constant.
This constant was always `true` when code was able to include
`<scry/reflection.hpp>`. The reason is that the optional reflection component
and a supported reflection compiler are already necessary for that header. Use
the package component and the target as the capability boundary:

```cmake
find_package(scry 0.2.0 CONFIG REQUIRED COMPONENTS reflection)
target_link_libraries(app PRIVATE scry::reflection)
```

Remove source checks of `scry::reflection::enabled`. No runtime-disabled state
exists, so these checks have no replacement. The reflection component is still
experimental. This removal has no effect on the stable C++23 core package.

## Changed

- Accepted turns share immutable snapshots of the conversation history and the
  tool schemas. They do not make deep copies of these snapshots. The commit of a
  Conversation uses copy-on-write only while another request still holds the
  history snapshot.
- The public `Error` layout and the state of the OpenAI streaming decoder use
  more compact representations. The meaning of errors and the output of the
  decoder do not change.
- This release adds an opt-in, build-only profiling suite. The suite gives
  deterministic scenarios, allocation-pressure tracking, artifact validation,
  and paired comparisons on the same host. It does not add a runtime dependency
  or a dependency of the installed package.

## Fixed

- The arithmetic for retry deadlines now saturates at the maximum of the steady
  clock. It does not overflow when a time point or a duration from the
  configuration is near its representable limit.

## Upgrade

Update FetchContent pins to `v0.2.0` or request
`find_package(scry 0.2.0 CONFIG REQUIRED)`. Reorder all `scry::Error` aggregate
initializers. Remove all uses of `scry::reflection::enabled`. Rebuild the
dependents.

Scry is still pre-1.0. The API, the ABI, and the formats for persisted
conversations can change between releases.

This release affects these requirements: SCRY-THR-003, SCRY-LOOP-005,
SCRY-TOOL-003, SCRY-NET-005, SCRY-PORT-007, and SCRY-QA-014.
