# Scry v0.2.0

Scry v0.2.0 reduces allocation pressure in accepted turns and streaming
decoders, adds a reproducible profiling workflow, and hardens retry deadline
arithmetic. The minor version bump signals a source and ABI break in the public
`scry::Error` aggregate. It also removes an information-free constant from the
experimental reflection component.

## Breaking changes

### `scry::Error` member order

The declaration order of `scry::Error` members is now:

1. `category`
2. `retryable`
3. `attempt`
4. `message`
5. `provider_detail`
6. `retry_after`
7. `turn_id`
8. `provider_request_id`

The scalar fields moved together to reduce padding in each error carried by
value. C++ designated initializers must follow declaration order, so consumers
that initialize fields in the v0.1.x order must reorder them. Positional
aggregate initialization must also be updated, and binary consumers must be
rebuilt for the new layout. Prefer designated initialization in the new order:

```cpp
scry::Error error{
    .category = scry::ErrorCategory::network,
    .retryable = true,
    .attempt = 2,
    .message = "request failed",
};
```

`scry::ErrorCategory` itself is unchanged: its enumerators and their underlying
numeric values retain the v0.1.x order.

### Reflection capability constant removed

The experimental `scry::reflection::enabled` constant has been removed. It was
always `true` whenever `<scry/reflection.hpp>` could be included because the
header already requires the optional reflection component and a supported
reflection compiler. Consumers should use the package component and target as
the capability boundary:

```cmake
find_package(scry 0.2.0 CONFIG REQUIRED COMPONENTS reflection)
target_link_libraries(app PRIVATE scry::reflection)
```

Remove source checks of `scry::reflection::enabled`; there is no runtime-disabled
state to replace them with. The reflection component remains experimental, and
this removal does not affect the stable C++23 core package.

## Changed

- Accepted turns share immutable conversation-history and tool-schema
  snapshots instead of deep-copying them. Conversation commit uses copy-on-write
  only while another request still retains the history snapshot.
- The public `Error` layout and OpenAI streaming decoder state use more compact
  representations while preserving error meaning and decoded output.
- An opt-in, build-only profiling suite now provides deterministic scenarios,
  allocation-pressure tracking, artifact validation, and same-host paired
  comparisons. It does not add a runtime or installed-package dependency.

## Fixed

- Retry deadline arithmetic now saturates at the steady clock maximum instead
  of overflowing when a time point or configured duration approaches its
  representable limit.

## Upgrade

Update FetchContent pins to `v0.2.0` or request
`find_package(scry 0.2.0 CONFIG REQUIRED)`, reorder any `scry::Error` aggregate
initializers, remove uses of `scry::reflection::enabled`, and rebuild dependents.

Scry remains pre-1.0: API, ABI, and persisted conversation formats may change
between releases.

Affected requirements: SCRY-THR-003, SCRY-LOOP-005, SCRY-TOOL-003,
SCRY-NET-005, SCRY-PORT-007, and SCRY-QA-014.
